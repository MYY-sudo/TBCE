Milestone 11 - Project dashboard: production bundle inspection
Date: 2026-09-19
Build: npm run tauri build -- --target x86_64-pc-windows-msvc
Bundle: dist/ as produced by that build (Vite 7, production mode)

Milestones 6 to 10 checked that the development-only Git harness does not ship,
that the webview names no GitHub host, that the webview sends no write method,
and that no component sets inner HTML. All four are rechecked. The dashboard
shows a repository description, milestone titles and commit summaries written
by other people, so the inner-HTML check matters here too.

$ grep -rl "tbce-git-harness-dev-only" dist/
(no matches)

$ grep -rl "api.github.com" dist/
(no matches)

The API host still appears nowhere in the bundle. Commands are named, never an
endpoint, and the three the dashboard added are among them:

Searched across every asset, the same pattern also matches one string in
Monaco's TypeScript worker, ts.worker-*.js: a compiler diagnostic key that
spells out a github.com URL in words ("..._Slashgithub_com_Slash..."). It is
not a command and names no API host.

$ grep -rlE "\"(POST|PATCH)\"" dist/assets/
(no matches)

$ grep -rln "dangerouslySetInnerHTML\|innerHTML" src/
(no matches)

$ grep -c "dangerouslySetInnerHTML" dist/assets/index-*.js
1

React's own runtime names the property, which is why the bundle count is not
zero; no TBCE source file uses it or innerHTML, which is the claim that
matters.

$ ls dist/assets | grep -iE "harness|github|issue|pull|patch|diff|dashboard"

The dashboard is a lazy chunk of its own, loaded the first time it is shown,
like DiffView and PullFileView. The dashboard store and the shared Recent list
ship in the main entry chunk, because the application shell uses both. The
other lazy chunks are unchanged: Editor and TerminalPanel.
