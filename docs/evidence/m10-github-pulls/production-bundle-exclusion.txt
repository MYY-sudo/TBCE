Milestone 10 - GitHub pull requests: production bundle inspection
Date: 2026-09-18
Build: npm run tauri build -- --target x86_64-pc-windows-msvc
Bundle: dist/ as produced by that build (Vite 7, production mode)

Milestones 6 to 9 checked that the development-only Git harness does not ship,
that the webview names no GitHub host, and that no component sets inner HTML.
All three are rechecked. Pull request descriptions and patches are text from
other people, like issue bodies, so the inner-HTML check matters as much here.

$ grep -rl "tbce-git-harness-dev-only" dist/
(no matches)

$ grep -rl "api.github.com" dist/
(no matches)

The API host still appears nowhere in the bundle. The pull request commands
are named, never an endpoint:

$ grep -o "github_[a-z_]*pull[a-z_]*" dist/assets/index-*.js | sort -u
github_pull_files
github_pull_request
github_pull_requests

$ grep -rlE "\"(POST|PATCH)\"" dist/assets/
(no matches)

$ grep -rln "dangerouslySetInnerHTML\|innerHTML" src/
(no matches)

$ grep -c "dangerouslySetInnerHTML" dist/assets/index-*.js
1

React's own runtime names the property, which is why the bundle count is not
zero; no TBCE source file uses it or innerHTML, which is the claim that
matters.

$ ls dist/assets | grep -iE "harness|github|issue|pull|patch|diff"
DiffView-DmViA7up.js
PatchView-C548r5zk.js
PullFileView-1KFNM3BE.js

The Pull requests tab ships inside the main entry chunk with the rest of the
GitHub panel. The shared Monaco patch view is now its own lazy chunk,
PatchView, loaded by both lazy wrappers: DiffView for a local diff and
PullFileView for a pull request file. Neither loads until a patch is opened.
The other lazy chunks are unchanged: Editor and TerminalPanel.

$ grep -o "connect-src[^\"]*" src-tauri/tauri.conf.json
connect-src ipc: http://ipc.localhost; worker-src 'self' blob:

$ grep -o "img-src[^;]*" src-tauri/tauri.conf.json
img-src 'self' data:

The content security policy is unchanged by this milestone
(git diff HEAD -- src-tauri/tauri.conf.json is empty). The webview can make
no request of its own and load no remote image, so an image link in a pull
request description could not load even if it were rendered, which it is not.
